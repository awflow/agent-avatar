# Plan 4 — Framework adapters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One live-avatar handle in the core (`mount()`), and components for Svelte, React, Vue, Solid and a `<awf-avatar>` custom element — each with `AvatarGroup` — that render the same bytes as `toSvg` and drive the same rig.

**Architecture:** The core gains `mount.ts`, a DOM-side handle that owns a rendered `<svg>` and a `Live`, applying option changes either as identity changes (re-render + new `Live`) or state changes (`setExpression`/`setActivity`/`setGaze`/`ring`). Framework components render the static tree for SSR (Peek's pattern: the tree only changes when identity changes, the rig writes the DOM afterwards) and hand the mounted `<svg>` to the handle. Groups compute gaze toward the speaker with `lookAt`.

**Tech Stack:** Svelte 5 + `@sveltejs/package`; React ≥ 18 (`useId`, `useImperativeHandle`); Vue 3 render functions (`h`), `@vue/server-renderer`; Solid 1.9 + `vite-plugin-solid`; vitest + jsdom per adapter.

**Spec:** `docs/superpowers/specs/2026-10-17-awflow-avatar-design.md` (§7.9, §7.6 group gaze)

## Global Constraints

- Roadmap shared constraints apply.
- Every adapter accepts the same props: `name` (required), `size`, `theme`, `style`, `version`, `framing`, `frame`, `square`, `expression`, `activity`, `gaze` (`[x,y] | 'pointer'`), `animate`, `fx`, `ring`, `dress`, every identity axis (`shape`, `color`, `eyes`, `brows`, `mouth`, `cheeks`, `trait`, `motif`), wardrobe (`headwear`, `eyewear`, `neckwear`, `face`), `prop`, `title`, `riso`, plus `class`/`className` and `style` passthrough. Imperative handle: `react(name)`, `pulse(strength?)`, `setVoice(fn|null)`, `lookAt(target|null)`.
- Declarative reactions: props `reaction` + `reactKey` (fires when `reactKey` changes and `reaction` is set).
- SSR output of every adapter, canonicalised (Peek's `canon()`), equals `toSvg(name, sameOpts + sameId)`.
- Each adapter package depends on `@awflow/avatar` (`workspace:^`) and lists its framework as a peer dependency only.

- Controller rulings (from Plan 2's final review): the whole `ring` option is state (forwarded to `Live.setRing`), never an identity change and never part of an adapter's re-render key. Animated SSR emits the **live** tree (`settle(name, opts, true)` + `draw`), not pruned `toSvg` output, so `attach()` binds node-for-node; `Live.bind()` verifies tag and child count and throws a descriptive error on mismatch. SSR parity against `toSvg` applies to non-animated avatars; animated SSR parity compares against the serialized live tree. Adapters pass the initial `activity` to `restPose`/`Live`.

## Review Focus

1. **Identity change while animating** — changing `name`/`shape`/`theme` on a live avatar; expected: re-render with the new identity and a fresh rig, no orphaned loop (Live count stays constant). Test in Task 1.
2. **Unmount mid-reaction** — component destroyed during `react('celebrate')`; expected: loop stops, no errors after unmount. Test in Task 1.
3. **Hydration** — SSR then hydrate with `animate`; expected: no hydration mismatch warnings (React/Vue/Svelte) and the first painted pose equals the server pose. Tests in Tasks 2–4.
4. **Group membership changes** — adding/removing an avatar from an `AvatarGroup` or changing `speaker` to a missing name; expected: gaze updates, missing speaker = everyone uses own gaze. Test in Task 7.
5. **Element attributes as strings** — `<awf-avatar size="64" gaze="0.2,-0.4" animate>`; expected: parsed numbers/arrays/booleans, invalid values ignored. Test in Task 6.

### Task 1: Core `mount()` handle

**Files:**
- Create: `packages/avatar/src/mount.ts`; export from `src/index.ts` and `src/adapter.ts`
- Test: `packages/avatar/src/mount.test.ts` (happy-dom)

**Interfaces:**
- Produces:
  ```ts
  export type AvatarHandle = {
    readonly element: SVGSVGElement
    set(patch: Partial<MountOptions>): void
    react(name: Reaction): void
    pulse(strength?: number): void
    setVoice(source: (() => number) | null): void
    lookAt(target: AvatarHandle | Element | null): void
    destroy(): void
  }
  export type MountOptions = AvatarOptions & { name: string; gaze?: Gaze | 'pointer'; animate?: boolean; reaction?: Reaction; reactKey?: unknown }
  export function mount(target: Element, opts: MountOptions): AvatarHandle      // renders into target (replaces children)
  export function attach(svg: SVGSVGElement, opts: MountOptions): AvatarHandle  // adopts an SSR-rendered <svg>
  export function isIdentityChange(prev: MountOptions, next: MountOptions): boolean
  ```
- `isIdentityChange` = anything that changes `JSON.stringify([settle(...).who, settle(...).opts])` except state keys (`expression, activity, gaze, ring, reaction, reactKey`); identity change → re-render the svg and recreate `Live` (old one destroyed); state change → forward to `Live`. Without `animate`, state changes re-render statically.
